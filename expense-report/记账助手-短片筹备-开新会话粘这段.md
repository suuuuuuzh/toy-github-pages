## 涉及的文件

- `expense-report/data-prep.js` =「报销单 · 短片筹备」（**你只改这个**）
- `expense-report/reports.js` = 登记表，改完要更新 `prep` 这条的 `count` 和 `total`

## 记账规则

往 `data-prep.js` 的 `expenseItems` 数组追加对象，id 用现有最大 id+1：

```js
{ id, category, description, date: "2026-08-XX", amount, voucherType: "none",
  invoiceFile: "", invoiceFiles: [], invoiceCategory: "", invoiceAmount: "",
  tpiaoIds: [], remark }
```

- `category` 只能从该文件的 `categoryOptions` 里选：
  创意阐述 / 脚本绘制费 / 美术筹备 / 道具购买 / 道具租金 / 服装-发套 / 器材租赁 /
  场地-看景 / 交通费 / 餐费 / 住宿费 / 办公用品 / 快递费 / 人员费（定金-预付）/
  业务招待费 / 前期杂支 / 其他
- `description` 简洁（如「8/13 美术看料市场打车」），商户名和订单号写进 `remark`
- 有发票文件时 `voucherType` 改 `"invoice"`，`invoiceFile` 填路径
- 记完更新 `expense-report/reports.js` 里 slug 为 `prep` 那条的 `count` 和 `total`（两位小数）

## 发票 / 截图处理

她发来的文件放进 `expense-report/invoices/extra/`，文件名规范：

```
日期_说明_[抵票/付款截图]_金额.扩展名
例：2026-08-13_买布料样品_180.00.pdf
    2026-08-13_美术看料打车_付款截图_42.00.jpg
正式发票不加中间那个标记
```

放完运行 `python3 expense-report/tools/gen_extra_manifest.py` 更新清单，再把路径填进条目的
`invoiceFile` / `invoiceFiles`。文件名含「抵票」会自动标抵票、含「截图」标付款截图。

对话里的内嵌图片无法保存成文件——遇到这种情况先把信息记进条目，提醒她用**文件形式**重发，
或她自己在网页上传。

## 发布流程（每次记完必须做，网站才会更新）

1. `git add <改动的文件> && git commit`（提交信息末尾加
   `Co-Authored-By: Claude <noreply@anthropic.com>` 和本会话的 Claude-Session 链接）
2. `git push -u origin claude/expense-report-webpage-halv71`
3. 发布到 main：
   ```
   git fetch origin main
   git checkout -B pub origin/main
   git checkout claude/expense-report-webpage-halv71 -- <改动的文件>
   git commit -m "Publish: ..."
   git push origin pub:main
   git checkout claude/expense-report-webpage-halv71
   git branch -D pub
   ```
4. **重要**：只 checkout 你改过的**具体文件**到 pub，不要整个目录覆盖——main 上有用户从
   网页直传的发票和自动生成的 `invoices-extra.js`，会被旧版本盖掉。要动 `invoices/extra`
   或 `invoices-extra.js` 时，先
   `git checkout origin/main -- expense-report/invoices expense-report/invoices-extra.js`
   同步最新再操作。
5. reports.js 是几张表共用的文件，改之前先 `git pull --rebase`，避免和别的记账会话冲突。
6. `git push` 偶尔会被权限分类器拦：先重试一次，不行就用 GitHub MCP 工具
   （`mcp__github__push_files`）推送。
